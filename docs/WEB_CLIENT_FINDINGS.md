# 웹 클라이언트에서 본 게이트웨이 — 실측과 처리

브라우저가 이 게이트웨이에 직접 붙을 때 무엇이 되고 무엇이 깨지는지를, 예측이 아니라
실제로 돌려서 확인한 기록이다. 프록시를 두지 않고 **게이트웨이와 다른 오리진**에서
페이지를 서빙해 브라우저가 진짜 CORS·스트리밍 규칙을 적용하게 했다.

프로브 하네스는 별도 레포(`cg_web`)에 있다.

## 되는 것

| 기능 | 근거 |
|---|---|
| 멀티턴 대화 | `/sessions` + SSE 로 문맥 유지 확인 |
| 토큰 단위 스트리밍 | `include_partial_messages` → `content_block_delta` 조각을 이어붙여 최종 텍스트 복원 |
| **도구 실행 승인 UI** | `hook_request` → 브라우저에서 `POST /hook_response` → 도구 실제 실행 |
| 서버측 도구 정책 강제 | `hook_rules` block — 클라이언트가 뭘 보내든 못 뚫음 |
| 여러 관전자 | broadcast 채널이라 탭마다 독립 수신 |
| 끊긴 스트림 재개 | `Last-Event-ID` |

"Claude 가 Bash 를 실행하려 합니다 [허용/거부]" 다이얼로그가 실제로 성립한다.

## 고친 것

| 발견 | 처리 |
|---|---|
| `include_partial_messages` 가 `json_decode` 에러만 냄 — CLI 는 `event`, 게이트웨이는 `stream_event` 키를 기대 | `a396185` |
| `Last-Event-ID` 무시 — 재연결마다 대화 전체 재전송 | `fccbe50` (세션 단위 안정 일련번호 + `?replay=all\|last\|none`) |
| CORS: 빈 목록·오타가 곧 전체 허용, credentials 불가 | `1137624` |
| 설정 로드 실패를 `unwrap_or_default()` 가 삼켜 전체가 기본값으로 되돌아감 | `1137624` (exit 2) |
| 요청이 `cli_path`·`env`·`mcp_servers`·`permission_mode`·`cwd` 를 자유롭게 지정 | `50bc1da` (`request_options.policy`) |

부수적으로 잡힌 것: hook 타임아웃 이중 계산(`36d7d4d`), auto-resolve 된 hook 의 구분
불가(`5d8d20e`), `/stats` 미집계(`4b01c24`).

## 남긴 것 — 세션 소유권

**게이트웨이에 "누구의 세션인가"라는 개념이 없다.**

- `GET /sessions` 는 모든 호출자의 세션을 나열한다
- `/sessions/:id/stream` · `/send` · `DELETE` 에 소유권 검사가 없다
- session_id 는 UUIDv4 라 추측은 어렵지만, 목록이 그걸 무의미하게 만든다

브라우저 프로브에서 실측됐다 — 페이지가 만들지 않은 세션을 목록에서 찾아 그 스트림을
구독했다.

**앞단 프록시로 덮이지 않는다.** 로그인을 붙여도 로그인한 사용자끼리는 서로의 대화가
보인다. 막으려면 프록시가 "이 사용자가 이 session_id 를 만질 수 있는가"까지 알아야
하는데, 그러려면 게이트웨이 밖에 세션↔사용자 매핑을 따로 두게 된다.

### 왜 여기서 멈추는가

앞의 다섯 건은 **방향 결정이 필요 없는 수정**이었다. 파싱은 CLI 출력에 맞추면 되고,
`Last-Event-ID` 는 SSE 규격이 있고, CORS 기본값은 어느 쪽이 안전한지 명확하고,
옵션 정책은 노출 여부로 판정할 수 있었다.

소유권은 다르다. 식별자를 어디서 받을지(프록시가 넣는 헤더 · 토큰 · 쿠키), 테넌트
단위가 무엇인지, 기존 단일 사용자 배치와 어떻게 공존할지 — 전부 **제품 결정**이고,
그 결정은 이 레포의 원작자 몫이다. 우리가 임의로 모델을 박으면 상류가 다른 선택을
했을 때 되돌리기 어려운 표면(엔드포인트 시그니처, 세션 스키마)이 굳는다.

그때까지의 운영 전제:

- 게이트웨이는 **단일 신뢰 사용자용**이다
- 여러 사용자에게 열려면 **사용자마다 게이트웨이 인스턴스를 분리**한다 (세션이
  프로세스 메모리에 있으므로 어차피 수평 확장이 안 되고, 인스턴스 분리가 격리와
  용량을 동시에 해결한다)
- 그 배치에서도 `request_options.policy = "restricted"` 는 켜야 한다
